# Tuxity/Mattermost Enterprise Release Automation — Redo Design

**Date:** 2026-06-16
**Repo:** `tuxity/mattermost` (fork of `mattermost/mattermost`)
**Status:** Approved design, pending spec review → implementation plan

---

## 1. Background & problem

The fork republishes upstream Mattermost releases with a single custom change: a
license bypass that hands every server a permanent "Mr Robot @ fSociety" Enterprise
license, then builds & publishes enterprise artifacts (GitHub Release + `ghcr.io/tuxity/mattermost-enterprise-edition` Docker image).

### Current (broken) flow — as reverse-engineered

Two-stage pipeline:

1. **`sync-new-releases.yaml`** (cron daily + manual): compares upstream's latest
   GitHub Release vs the fork's latest. On a new upstream tag it does
   `checkout -B release-X.Y --track mattermost/release-X.Y` → `reset --hard <tag>` →
   **`git cherry-pick 06625acdaf`** (the enterprise commit, hardcoded SHA) →
   `tag <tag> --force` → force-push branch + tag.
2. **`server-ci-enterprise.yaml`** (push to `release-*` / `v*` tag): builds the
   enterprise edition, creates a GitHub Release with 5 platform artifacts, builds &
   pushes the Docker image.

### Root cause of the multi-week breakage

The enterprise commit **comments out and rewrites the middle of
`PlatformService.LoadLicense()`** in `server/channels/app/platform/license.go`
(~99 lines). Every upstream release that touches that function makes
`git cherry-pick 06625acdaf` conflict. The workflow has **zero conflict handling**,
so it exits non-zero, no branch/tag is pushed, and the fork freezes.

**Evidence:** fork stuck at `v11.5.1` while upstream is at `v11.8.0`/`v11.8.1`
(also `v11.5.7`, `v11.6.5`, `v11.7.4`). All `release-*` branches carry enterprise
commits dated 2024-05-17; `release-11.5` even carries an *older* enterprise commit
(`99d5bee861`, 4 files, no `Makefile`) than master's current `06625acdaf` (5 files).
History also holds ~20+ duplicate "enterprise license" commits from repeated redos.

## 2. Goals & decisions

- **Reliability:** sync must survive upstream edits to `LoadLicense()`.
- **Apply mechanism:** idempotent script (no `git cherry-pick`), fail-loud on missing anchors.
- **License injection:** unconditional early-return at the top of `LoadLicense()`.
- **Scope:** track the single latest upstream release ("latest only").
- **Cleanup:** full reset — rewrite `master`, delete stale `release-*` branches,
  regenerate latest. Force-push is acceptable.
- **Preserve:** all custom IP (the license bypass + build/sync workflows) and all
  **already-published** tags / GitHub Releases / Docker images (`v11.5.1` and older
  are kept; deleting them would break existing consumers).

## 3. The custom IP being preserved

Everything else in the fork is vanilla upstream (`claude.yml`,
`migration-assist-sync.yml`, etc. are upstream files). The only custom content:

1. `server/channels/app/platform/license.go` — the license bypass (re-expressed as early-return).
2. `server/enterprise/external_imports.go` — neutralize private-EE-module imports.
3. `server/Makefile` — `go work use $(BUILD_ENTERPRISE_DIR)`.
4. `server/build/Dockerfile` — `COPY --from=dist mattermost-* /tmp`.
5. `.github/workflows/server-ci-enterprise.yaml` — build/release/Docker workflow.
6. `.github/workflows/sync-new-releases.yaml` — sync workflow.
7. Constant: `ghcr.io/tuxity/mattermost-enterprise-edition`.

## 4. Target architecture

**Principle:** `master` stays clean and close to upstream; the enterprise hack only
exists on `release-*` branches, generated by a script at sync time.

```
master  =  upstream/master  +  ONE tooling commit:
             .tuxity/apply-enterprise.sh                 # idempotent applier
             .tuxity/license-inject.go.txt               # the early-return block (source of truth)
             .tuxity/workflows/server-ci-enterprise.yaml # canonical build workflow
             .tuxity/README.md                           # documents the setup
             .github/workflows/sync-new-releases.yaml    # rewritten sync workflow

release-X.Y  =  upstream tag vX.Y.Z  +  ONE generated commit
                "feat: add enterprise license for MrRobot@fSociety"
                  (license.go inject, external_imports stub, Makefile,
                   Dockerfile, .github/workflows/server-ci-enterprise.yaml)
```

`master` no longer carries a patched `license.go`; it compiles like vanilla upstream.
The IP lives as readable source under `.tuxity/` and is materialized onto release
branches. Each release branch still has the single "my commit", regenerated robustly.

> Note: the canonical `server-ci-enterprise.yaml` lives under `.tuxity/workflows/` on
> master (so it does not run on master), and the apply script copies it into
> `.github/workflows/` on each release branch where it should trigger.

## 5. The robust apply script — `.tuxity/apply-enterprise.sh`

Idempotent, fail-loud, run from repo root against a fresh upstream-tag checkout:

1. **license.go** — insert the early-return Enterprise-license block immediately after
   `func (ps *PlatformService) LoadLicense() {`. Anchored on that signature only;
   leaves the rest of the function and all imports untouched (Go compiles the now
   unreachable original body, so imports/vars stay "used"). Idempotent via a
   `// >>> tuxity-enterprise` marker. **Exit 1 if the anchor is missing.**
2. **external_imports.go** — overwrite with a stub that has no references to the
   private `github.com/mattermost/enterprise` module. Fully robust; no anchor needed.
   (Upstream guards this file with `//go:build enterprise`.)
3. **Makefile** — replace the `go work use ../../enterprise` line with
   `go work use $(BUILD_ENTERPRISE_DIR)`. Skip if already done; fail if line absent.
4. **Dockerfile** — insert `COPY --from=dist mattermost-* /tmp` after the
   `ARG MM_PACKAGE` line. Skip if present.
5. **Copy** `.tuxity/workflows/server-ci-enterprise.yaml` → `.github/workflows/server-ci-enterprise.yaml`.

Each step logs what it did. Any missing anchor is a hard failure so the sync workflow
fails loudly instead of producing a broken/unpatched build.

### Injected license block (source of truth: `.tuxity/license-inject.go.txt`)

Placed right after the opening brace of `LoadLicense()` (unconditional; the upstream
`MM_LICENSE` env override no longer applies, by decision):

```go
// >>> tuxity-enterprise (auto-injected by .tuxity/apply-enterprise.sh) >>>
f := model.Features{}
f.SetDefaults()
*f.Users = 9999
ps.SetLicense(&model.License{
    Id:        model.NewId(),
    IssuedAt:  0,
    ExpiresAt: 4102491600000, // 1 Jan 2100, in ms
    Customer: &model.Customer{
        Name:    "Mr Robot",
        Email:   "mrrobot@fsociety.com",
        Company: "fsociety",
    },
    Features:     &f,
    SkuName:      "Enterprise",
    SkuShortName: model.LicenseShortSkuEnterprise,
})
ps.logger.Info("License key is valid, unlocking enterprise features.")
return
// <<< tuxity-enterprise <<<
```

## 6. Rewritten sync workflow — `.github/workflows/sync-new-releases.yaml`

Keeps the existing compare-releases step (upstream vs fork latest). On a new tag:

```sh
cp -r .tuxity /tmp/tuxity                 # survive the reset
git remote add mattermost https://github.com/mattermost/mattermost.git
git fetch mattermost tag "$tag"
git checkout -B "release-$major_minor" "$tag"
/tmp/tuxity/apply-enterprise.sh
git add -A
git commit -m "feat: add enterprise license for MrRobot@fSociety"
git tag "$tag" --force
git push origin "release-$major_minor" --force
git push origin "$tag" --force
```

Add a **notify-on-failure** job step: Mattermost webhook if a secret is configured
(reusing the `mattermost/action-mattermost-notify` action already used in
`migration-assist-sync.yml`), otherwise rely on GitHub Actions' native failure email.

The tag push triggers `server-ci-enterprise.yaml` unchanged → build → GitHub Release +
ghcr image.

## 7. Cleanup & force-push plan

Ordered, with safety first:

1. **Back up (non-negotiable):**
   - `git bundle create tuxity-backup-2026-06-16.bundle --all`
   - push current `master` to `backup/pre-cleanup-2026-06-16`
   - tag current `06625acdaf` and `fe2252a5fc` so the exact custom commits are retained.
2. **Rebuild `master`:** fetch upstream master, reset onto it, add the single
   `.tuxity/` tooling commit, **force-push** `origin master`.
3. **Delete stale `release-*` branches** on `origin` (regenerable build inputs).
4. **Regenerate latest:** run the sync workflow once via `workflow_dispatch` →
   fresh `release-11.8` + `v11.8.0` (or whatever upstream "latest" is at run time).
5. **Keep** all already-published tags / GitHub Releases / Docker images.

## 8. Verification before go-live

Before any force-push to `origin`:

1. Dry-run `apply-enterprise.sh` against `v11.8.0` in a throwaway worktree.
2. Confirm the patched tree **compiles** — `make build-cmd` (or at minimum
   `go build ./...` on `server/channels/app/platform`) — proving the early-return
   approach works against today's real upstream code.
3. Only then proceed with the cleanup steps in §7.

## 9. Out of scope (YAGNI)

- Tracking multiple maintained release series (latest-only by decision).
- Deleting/altering already-published releases, tags, or Docker images.
- Public-key-swap license strategy (considered, rejected as larger redesign).
- Any refactor of unrelated upstream workflows.

## 10. Risks & mitigations

| Risk | Mitigation |
| --- | --- |
| Upstream renames/changes `LoadLicense` signature | Script exits 1 → loud sync failure + notification |
| Unreachable-code/vet objections to early return | Verified via compile step (§8) before go-live |
| Force-push loses custom commits | Full backup bundle + backup branch + tags (§7.1) |
| `external_imports.go` stub diverges from upstream needs | Intentional — fork lacks the private EE module; overwrite is the goal |
| Build needs placeholder EE dir | `server/enterprise/{placeholder.go,LICENSE}` confirmed present upstream |
